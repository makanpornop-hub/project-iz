# Резервирование и восстановление

Telegram — дополнительная копия отдельных документов. Он не заменяет согласованную резервную копию базы и файлового хранилища.

## Предлагаемый регламент — подтвердить перед эксплуатацией

- Полная резервная копия PostgreSQL и объектов ежедневно, хранение 30 дней.
- Отдельное хранилище копий, ограниченный доступ и шифрование на стороне выбранного сервиса.
- При таком расписании возможная потеря данных — до 24 часов. Если этого недостаточно, нужны WAL/PITR и более частое копирование объектов.
- Целевое время восстановления определить после пробного восстановления на реальном объёме; оно пока не измерено.
- Проверка восстановления ежемесячно и перед существенными изменениями инфраструктуры.

Версионирование S3 включается начальной настройкой, но версии в том же хранилище не защищают от потери всего сервера.

## Согласованная локальная копия через Docker

Выполняется администратором сервера. Для небольшой системы остановите web и worker на время копии, оставив PostgreSQL и storage работающими. Это обеспечивает согласованность файлов и метаданных.

```powershell
docker compose stop web worker
docker compose exec db pg_dump -U iz -d iz -Fc -f /tmp/iz-backup.dump
docker compose cp db:/tmp/iz-backup.dump ./backups/iz-backup.dump
```

Сначала создайте папку `backups`. Отдельно скопируйте все объекты приватного bucket с помощью инструмента выбранного S3-провайдера. Сохраняйте неизменённые ключи объектов. Для MinIO можно использовать `mc mirror` с авторизованными псевдонимами источника и отдельного backup bucket. Не помещайте ключи доступа в репозиторий или команды, публикуемые в переписке.

Проверьте завершение обеих копий, запишите дату, число объектов и контрольные суммы. Только после этого запустите:

```powershell
docker compose start web worker
```

## Пробное восстановление

1. Разверните **отдельный** PostgreSQL и приватный bucket; не восстанавливайте поверх действующей системы.
2. Восстановите дамп через `pg_restore --no-owner` в пустую базу. Используйте совместимую или более новую версию PostgreSQL.
3. Восстановите объекты с теми же ключами в тестовый bucket.
4. Подключите отдельный экземпляр приложения к восстановленным сервисам. Telegram и SMTP оставьте выключенными, фоновые внешние отправки не запускайте.
5. Проверьте вход, количество дел и версий, связи, выборочное скачивание файлов и совпадение контрольных сумм.
6. Запишите длительность восстановления и обнаруженные расхождения.

## Ограничение текущей проверки

Рабочее резервирование и полное восстановление реального S3/PostgreSQL в этой среде не выполнялись: сервисы и место хранения копий не предоставлены. Пошаговая инструкция не является подтверждением успешного восстановления. Автоматическое расписание копий на компьютере пользователя не создавалось.
