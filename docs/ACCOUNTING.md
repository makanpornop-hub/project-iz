# Бухгалтерия Project Iz

## Что добавлено

Модуль встроен в существующую CRM Next.js / React / PostgreSQL. Основной раздел — `/accounting`, вкладка дела — «Бухгалтерия». Финансы связаны с `cases.id`, а не с клиентом в целом.

В разделе доступны обзор, платежи клиентов, расходы, ожидаемые платежи, отчёты и настройки типов расходов. В деле доступны условия договора, первичный взнос и его дата, платежи, остаток, дедлайн, расходы, прибыль и финансовый отчёт. Рассчитанные значения не редактируются вручную. Валюта — сум; расчёты выполняются целыми сотыми долями через BigInt и PostgreSQL NUMERIC.

Возврат вводится положительной суммой с типом «Возврат» и вычитается из оплаты. Переплата отображается отрицательным остатком. Удаление операции мягкое: запись остаётся в истории и аудите. Изменения имеют номер редакции; устаревшая форма не перезаписывает чужую правку. Повторная отправка одинаковой операции с тем же идентификатором не создаёт дубль.

## API

В соответствии с существующей архитектурой:
- `GET /api/data/accounting` — обзор/отчёт; параметры `case_id`, `from`, `to`, `country`, `visa`, `owner`, `payment_status`, `financial_status`, `expense_type`.
- `POST /api/data/accounting` — действия `accounting.contract.save`, `accounting.payment.save`, `accounting.payment.delete`, `accounting.expense.save`, `accounting.expense.delete`, `accounting.type.save`.
- `POST /api/accounting/receipts` — файл и `case_id`, до 20 МБ, существующее хранилище и антивирус.
- `GET /api/documents/:versionId` — скачивание чека после проверки финансовых прав.

Изменение/удаление передаёт `id` и `revision`; новая операция — `request_key` UUID. Для условий оплаты передаётся редакция финансов дела.

Отчётные фильтры выбирают дела и операции. Договор, остаток, плановая прибыль — текущие полные итоги выбранных дел. «Получено за период» и «Расходы за период» учитывают только даты и выбранный тип расхода. Отчёты доступны на экране; экспорт в Excel/PDF не запрашивался и не добавлялся.

## Статусы

Состояние оплаты хранится отдельно от workflow дела. `PAYMENT_OVERDUE` возникает, если локальная календарная дата компании позже дедлайна и остаток положителен. В день дедлайна просрочки нет. `EXPENSES_EXCEED_PAYMENTS` возникает при превышении расходов над чистой оплатой клиента. При обоих условиях — `FINANCIAL_ATTENTION` и две отдельные причины. За три дня до оплаты — `PAYMENT_DUE_SOON`.

После устранения причины предупреждение снимается. Повторное возникновение создаёт новый финансовый эпизод. Полная оплата даёт `PAID`, если нет другой критической причины. Неуказанный договор не считается нулевым оплаченным договором. Основной статус визового дела не заменяется финансовым.

В списке визовых дел критические строки выделяются; показываются причины, задолженность, дедлайн и дни просрочки в пределах прав пользователя. В делах показываются дни/часы до срока и прогресс обязательных документов. С 07.10.2026 загрузка файлов не меняет этап дела: «Подготовка документов» выбирается вручную.

## Telegram и scheduler

Используется существующий Telegram Bot API на сервере и очередь `jobs`. Переменные:

```dotenv
TELEGRAM_BOT_TOKEN=<существующий секретный токен>
TELEGRAM_FINANCE_CHAT_ID=-5519700066
```

Обе переменные настроены. Через read-only Telegram API подтверждено, что бот состоит в группе и может писать. Внутренние уведомления получают активные администраторы. У каждой критической причины есть отдельное событие и уникальная задача доставки. Сбой Telegram не откатывает финансовую операцию; существующий worker повторяет доставку с задержкой. После восьми неудачных попыток задача отмечается ошибкой. История события показывает состояние доставки. В редкой ситуации «Telegram принял сообщение, но ответ потерян» Bot API не гарантирует строго однократную доставку; повторный cron сам по себе дублей не создаёт.

Отдельный системный cron не требуется: `scripts/worker.ts` создаёт проверку `finance_check` при запуске и затем каждый час. Повторные процессы защищены уникальным ключом часа. Существующие START.cmd / scripts/local.ps1 запускают worker независимо от открытого браузера. Для работы при выключенном компьютере потребуется перенос CRM на постоянно работающий сервер.

## Права и аудит

Добавлены `accounting.view`, `accounting.manage`, `accounting.view_contract`, `accounting.view_profit`, `payments.create`, `payments.edit`, `expenses.create`, `expenses.edit`, `expense_types.manage`.

Администратор получил все права. Обычные сотрудники автоматически их не получили. Доступ ограничен также существующими правилами доступа к визовому делу. Договор, остаток и плановая прибыль без соответствующих прав исключаются из ответа API, а не только скрываются в интерфейсе. Чеки и финансовые детали аудита не выдаются через обычную карточку дела. Назначение прав — Бухгалтерия → Настройки → ссылка на роли.

Аудит финансовых изменений содержит автора, старые и новые значения и время. Для типов расходов используется деактивация; старые операции сохраняют снимки названия/категории.

## Что вводится пользователем

Открыть визовое дело → Бухгалтерия → Условия оплаты и указать договор и дедлайн. Затем вносить реальные платежи и расходы; при необходимости настроить типы и права сотрудников. Исторические финансовые суммы не были придуманы или заполнены автоматически.
