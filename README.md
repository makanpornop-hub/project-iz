# Project Iz

Внутренняя система визового офиса. Интерфейс на русском: дела клиентов, документы и версии, задачи и сроки, сотрудники и права, Telegram и журнал действий.

## Готовый запуск на этом компьютере

Сайт установлен и настроен в `C:\Project Iz`. Откройте http://localhost:3000.

- `START.cmd` запускает сайт и все службы. После перезагрузки компьютера запустите его снова.
- `STOP.cmd` останавливает службы.
- `BACKUP.cmd` сохраняет согласованную копию базы и документов в `backups`; сайт на время копирования останавливается и затем запускается снова.
- Логин и пароль администратора находятся в защищённом файле `Доступ.txt`.
- Локальная почта: http://localhost:8025. Письма восстановления пароля и приглашения доступны здесь; внешним адресатам они не отправляются.
- Бот @Withyou1313_bot подключён. В своём профиле нажмите подключение Telegram, перейдите по полученной ссылке и нажмите Start. Это связывает именно ваш личный Telegram с учётной записью сайта.

PostgreSQL 17.11, MinIO, ClamAV 1.4.6, Mailpit и Node.js установлены в `.runtime`. Рабочие данные находятся в `.data`; журналы — в `.logs`. Все службы слушают только этот компьютер (127.0.0.1). Docker для этой установки не нужен. Не переносите папку при запущенных службах: сборка содержит ссылки на текущий путь.

Проверены реальная авторизация, закрытый доступ, чтение разделов, запись и чтение версионного файла, антивирусная проверка и соединение SMTP. Первая резервная копия успешно восстановлена в отдельную проверочную базу. В рабочей базе нет тестовых клиентов. Копия на том же диске не защищает от потери этого диска; внешнее место хранения ещё не задано.

Сайт не опубликован в интернете. Для совместной работы с других компьютеров потребуется отдельная настройка сервера и HTTPS. Telegram получает обновления через исходящее соединение: публичный адрес не требуется. Telegram-группы для документов и уведомлений не заданы; отправка документов в группы выключена.

Далее приведены исходные инструкции для отдельной установки через Docker. Не выполняйте их поверх уже настроенной локальной установки.

## Договор и бухгалтерия при создании дела

В «Новое визовое дело» время срока по умолчанию — **08:05** по часовому поясу компании. Дата выбирается отдельно. В блоке «Бухгалтерия и договор» укажите валюту UZS/USD/EUR, договорённую сумму, первичный взнос, способ оплаты и срок оплаты остатка. При полном первичном взносе срок остатка скрывается. Условия и первичный платёж сохраняются вместе с делом.

Администратор загружает собственный договор DOCX в **Настройки → Шаблон договора DOCX** (`/settings/contracts`). В Word замените переменные места на метки:

| Метка | Подстановка |
| --- | --- |
| {{CLIENT_NAME}} | Полное имя клиента из CRM |
| {{DATE}} | Дата создания договора, дд.мм.гггг, по часовому поясу компании |
| {{TOTAL_AMOUNT}} | Общая сумма в выбранной валюте |
| {{INITIAL_PAYMENT}} | Первичный взнос, 0,00 при отсутствии |
| {{CURRENCY}} | UZS, USD или EUR |

Обязательны все пять меток. Их можно повторять в тексте, таблицах и колонтитулах; Word может разбивать метку на несколько фрагментов форматирования. Импорт поддерживает DOCX до 5 МБ и выполняет антивирусную проверку.

При сохранении нового дела договор создаётся автоматически и прикрепляется в «Документы → Договор клиента». Начальный статус дела — **Подписывается договор**. «Скачать предварительный договор» позволяет посмотреть черновик, но его скачивание не требуется для сохранения. Нужны импортированный шаблон, ФИО клиента, ответственный, валюта и договорённая сумма. Если договор не удаётся создать, дело и платёж не сохраняются частично. Договор защищён правами просмотра бухгалтерии и скачивания документов.

Задача «Назначить дату билета в Испанию» открывается отдельной страницей. Сотрудник выбирает дату и время в самой задаче; ответственного и сотрудника для эскалации меняют только администратор и менеджер с правом назначения задач.

## Быстрый запуск на Windows через Docker Desktop

1. Установите Docker Desktop с поддержкой Linux containers и запустите его.
2. В PowerShell перейдите в папку проекта:

```powershell
Set-Location -LiteralPath 'C:\Project Iz'
Copy-Item -LiteralPath '.env.example' -Destination '.env'
```

3. Откройте `.env` и задайте случайные значения `POSTGRES_PASSWORD`, `BETTER_AUTH_SECRET` (не менее 32 символов), `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (не менее 8 символов). Не используйте `CHANGE_ME`. Пароль PostgreSQL для примера подключения должен состоять из букв и цифр; специальные символы в URL требуют кодирования.
4. Значение `BETTER_AUTH_URL` оставьте `http://localhost:3000` для локальной работы. Заполните `S3_BUCKET=iz-documents`.
5. Запустите:

```powershell
docker compose up -d --build
docker compose run --rm worker pnpm admin:create
```

Вторая команда попросит имя, email и пароль первого администратора. Пароль не сохраняется в исходниках. Создать первого администратора можно только один раз.

6. Откройте **http://localhost:3000** и войдите созданным аккаунтом.

Первый запуск может занять несколько минут: загружаются образы и антивирусные базы. До готовности ClamAV документы сохраняются, но недоступны для скачивания. Проверка будет повторена автоматически.

Для остановки без удаления данных:

```powershell
docker compose stop
```

Не используйте `docker compose down -v` для рабочей системы: эта команда уничтожит тома с базой и файлами.

## Запуск без Docker, если сервисы уже установлены

Нужен Node.js 24 и pnpm. Установите зависимости из зафиксированного списка, заполните `.env` и выполните:

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm exec tsx scripts/initialize.ts
pnpm admin:create
pnpm build
pnpm start
```

В отдельном терминале из той же папки:

```powershell
pnpm worker
```

Без фонового процесса не отправляются уведомления, не выполняются проверка файлов и Telegram-загрузки. Для разработки вместо `pnpm start` используйте `pnpm dev`.

## Подключение почты

Укажите SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD и MAIL_FROM. Создание сотрудника ставит отправку приглашения в очередь; сотрудник устанавливает пароль по одноразовой ссылке. Восстановление пароля использует тот же SMTP.

Для локальной проверки писем есть Mailpit:

```powershell
docker compose --profile development up -d mail
```

Если приложение работает в Docker, задайте `SMTP_HOST=mail`, `SMTP_PORT=1025`; если на Windows — `SMTP_HOST=localhost`. Почтовый ящик тестового сервиса: http://localhost:8025. Mailpit не отправляет письма внешним адресатам; для настоящих приглашений нужен реальный SMTP.

## Подключение Telegram

1. Создайте своего бота через BotFather. В `.env` укажите токен и username без `@`.
2. Задайте случайный `TELEGRAM_WEBHOOK_SECRET` (буквы, цифры, `_` и `-`).
3. Разместите приложение на выбранном вами сервере с HTTPS; установите его адрес в `BETTER_AUTH_URL`.
4. Зарегистрируйте webhook:

```powershell
pnpm exec tsx scripts/telegram-webhook.ts
```

5. Сотрудник подключает аккаунт в разделе «Мой профиль» и открывает одноразовую ссылку.
6. Для копий файлов создайте приватный чат, добавьте туда бота с правом отправки файлов и заполните `TELEGRAM_BACKUP_CHAT_ID`. В «Настройках» включите отправку копий.

Участники Backup Chat видят все отправленные туда файлы, независимо от прав на сайте. По умолчанию отправка выключена, пока администратор не настроит и не включит её. Невключённые или неудачные отправки остаются в очереди/ошибках, доступны для повторного запуска.

Отправляйте изображения боту как **файл**, если нужен оригинал. Бот поддерживает выбор доступного дела, создание документа или версии и подтверждение. Незавершённую загрузку отменяет `/cancel`.

## Структура

- `src/app` — страницы и серверные HTTP-обработчики.
- `src/components` — интерфейс и необязательные инструменты браузерного агента.
- `src/lib` — права доступа, бизнес-операции, хранилище, Telegram и фоновые задания.
- `migrations` — структура PostgreSQL.
- `scripts` — запуск, начальная настройка и обслуживание.
- `tests` — изолированные проверки без настоящих клиентских документов.
- `docs` — архитектура, восстановление, результаты проверки.

Подробности: `docs/ARCHITECTURE.md`, `docs/BACKUPS.md`, `docs/VALIDATION.md`.

## Пароли сотрудников

Администратор может указать пароль при создании сотрудника в «Настройки → Сотрудники». Если пароль задан, приглашение по почте не требуется. Для существующего сотрудника доступна кнопка «Задать пароль». Минимальная длина — 12 символов. При смене пароля завершаются прежние сеансы и аннулируются старые ссылки восстановления; пароль не записывается в журнал. Свой пароль администратор меняет в профиле.

Вспомогательные файлы первоначальной установки и старая сборка перенесены с рабочего стола в `.runtime/setup-archive`. Рабочие скрипты находятся в `scripts`, данные — в `.data`.

## Информация партнёров

Раздел `/partners` доступен из бокового меню. «Новая группа» создаёт группу с названием; «Добавить партнёра» открывает форму прямо в этом разделе. Поля: имя, телефон, эмэйл, страна, город, заметки. Кнопки редактирования есть у группы и каждой карточки. При редактировании партнёра можно выбрать другую группу.

Просмотр доступен авторизованным сотрудникам. Право «Управление партнёрами» по умолчанию выдано администратору и менеджеру; его можно назначать через «Настройки → Роли и права». Контакты хранятся в PostgreSQL и входят в обычную резервную копию базы.

## Автоматический процесс «ВНЖ испания»

При создании нового дела с этим типом визы укажите отдельный дедлайн задачи «Назначить дату билета в Испанию». Система создаёт эту задачу и задачу «Собрать перечень документов». У второй задачи срок не назначается автоматически; его можно указать отдельно. Старые дела и остальные типы виз автоматически не меняются.

В карточке дела, на вкладке документов, появляется 15 групп: диплом; ЯТТ / ИП; справка о несудимости; Деклорация RETA; контракт; банковская выписка; фирма контрактник; декларация о несудимости; разрешение на работу; декларация о дипломе; анкета МИТ6; доверенность; CV; паспорт; Declaration De Entrada. Внутри — отдельные поля из вашего перечня. Печать ИП и сканы дополнительных ВНЖ/паспортов необязательны. Кнопка у справки создаёт следующую группу с номером. Можно добавлять группы и поля, изменять названия, обязательность и порядок объединения. Существующие поля с версиями не удаляются.

Для перечня подходят PDF/JPG/PNG до 20 МБ на файл. PDF объединяются постранично; изображения помещаются на страницы A4. Исходные файлы должны пройти ClamAV. Защищённые паролем или повреждённые PDF нужно заменить. Итоговый PDF сохраняется отдельной версией в поле результата и тоже проходит антивирусную проверку. Общий размер исходников для одного объединения — до 80 МБ, итогового файла — до настроенного лимита (по умолчанию 20 МБ), не более 1000 страниц.

В дипломе, ИП и справках порядок: пояснительное письмо → Jurado перевод → легализация → апостель. Оригинал хранится отдельно и не входит в объединение. Для выписки: пояснительное письмо → перевод транзакций → транзакции за три месяца → инвойсы. В остальных группах кнопка отсутствует, пока порядок объединения не задан вручную.

«Готово» проверяет обязательные поля, состояние антивируса и актуальность объединённых файлов. Всем активным администраторам создаётся уведомление; при привязанном Telegram оно доставляется ботом. Документы можно исправлять после отправки: пакет снова открывается для работы. Администратор одобряет пакет (задача завершается) или возвращает с комментарием (задача остаётся в работе). Завершить эту задачу обычной кнопкой статуса нельзя. Новая версия исходника делает прежний итоговый PDF неактуальным. Перечень и результаты входят в обычные резервные копии базы и хранилища.

## Компактный перечень, просмотр и проверка файлов

На широком экране группы документов показаны в две колонки с уменьшенными отступами. Под заголовком перечня отображаются количество загруженных обязательных полей, число незаполненных полей и процент заполнения. Необязательные поля и итоговые PDF в этот счётчик не входят; шкала показывает загрузку, а не одобрение.

Название загруженного и проверенного антивирусом файла открывает просмотр PDF/изображения внутри сайта. Рядом показан статус: «Новое», «Рассматривается», «Подтверждено». Открытие администратором переводит новую версию в «Рассматривается», кнопка «Подтвердить документ» — в «Подтверждено». Просмотр сотрудником статус не меняет. Новая версия получает статус «Новое». Просмотр не сбрасывает уже полученное подтверждение.

Перед одобрением всего пакета администратор должен подтвердить загруженные документы и итоговые PDF. Если сотрудник успел заменить файл, подтверждение прежней версии отклоняется: нужно открыть новую версию. Скачивание доступно отдельно от просмотра.

## Работа с клиентом и Telegram

При выборе существующего клиента в новом визовом деле автоматически заполняются имя, телефон и email. Страна, виза и ответственные задаются отдельно.

Для загрузки через подключённый Telegram отправьте файл, выберите дело клиента, группу перечня и поле. Файл сохраняется без дополнительного подтверждения и без обязательного перехода на сайт. Новая загрузка в заполненное поле создаёт новую версию. Группы и поля берутся из текущего перечня, включая добавленные вручную. Первичная привязка Telegram к сотруднику выполняется один раз в профиле.

## Завершение перечня и ZIP

Группы расположены в одной колонке и сворачиваются. Кнопка «Готово» подсвечивает незаполненные обязательные поля и прокручивает к первому из них. Также проверяются антивирус и актуальность объединённых PDF.

После успешной проверки создаётся ZIP с последними загруженными версиями всех документов перечня, включая необязательные загруженные поля и объединённые PDF. Внутри ZIP документы распределены по папкам групп. В разделе завершения появляется «Скачать ZIP», а администратор получает уведомление о готовности пакета. После возврата на доработку следующий клик «Готово» создаёт новый архив. Общий размер исходных файлов одного архива — до 512 МБ.


## Бухгалтерия

Раздел /accounting и вкладка в визовом деле: договор, платежи, возвраты, расходы, чеки, финансовые предупреждения, отчёты и настройки. Подробное описание API, прав, Telegram и часовых проверок — в docs/ACCOUNTING.md.


## Отдельные страницы настроек

В «Настройках» есть отдельные страницы «Шаблон договора DOCX» (`/settings/contracts`) и «Telegram-чаты» (`/settings/telegram`), доступные администратору.

В Telegram-настройках можно менять Chat ID для ZIP документов, резервных копий файлов, событий команды и бухгалтерских уведомлений. Для копий и событий команды есть отдельные переключатели. Сохранение применяется без перезапуска сайта и бота. Изменение чата ZIP действует на новые архивы; уже созданные архивы сохраняют первоначальный адрес отправки.

Список показывает настроенные группы/каналы и чаты, события которых получил бот. «Добавить / проверить чат» получает название и тип через Telegram без отправки сообщений или документов. Неизвестный боту чат можно добавить вручную по Chat ID после добавления бота в группу/канал. Личные чаты сотрудников остаются в профилях.

## Фильтры обзора и обязательные поля

В «Дела по этапам» нажмите статус: на той же странице появятся только дела этого этапа. «Требуют внимания», «На сегодня», «Мои задачи» и «Завершено» фильтруют список задач согласно соответствующим показателям. «Сбросить фильтр» возвращает обычный обзор. Счётчики показывают все доступные пользователю дела/задачи.

Администратор раскрывает «Обязательные поля нового дела» в форме создания, отмечает нужные поля и сохраняет выбор. Настройка действует на все следующие новые дела и проверяется на сервере. ФИО клиента, ответственный, валюта и сумма остаются обязательными для дела и договора. Дедлайн оплаты остатка не требуется при полной оплате. Старые дела не меняются.


## Этапы визовых дел

Обзор, список дел и редактирование используют единый список: Подписывается договор, Ожидание оплаты, Подготовка документов, Проверка документов, Готова к подаче, Ожидание решения, Одобрено, Дозапрос, Отказ.

Новое дело начинает с «Подписывается договор». Остальные ручные этапы меняются через редактирование дела. Загрузка файлов не меняет ручной этап. «Готово» в перечне после выбора даты создаёт ZIP, сохраняет напоминание и переводит дело в «Проверка документов». Одобрение всего пакета администратором завершает задачу и устанавливает «Готова к подаче»; возврат пакета или изменение документов на этих двух этапах возвращает «Подготовка документов». «Дозапрос» выбирается вручную. Перенос даты проверки не меняет этап.
